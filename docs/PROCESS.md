# 做一个段落的标准流程（所有 agent 和我自己都照这个走）

## 1. 读
`docs/PLAN.md` 中这一段那一行、`docs/VISUAL.md`、`research/senbon_study.md`，以及**前后相邻的已完成段落**的代码。
目的是知道：这一刻在电话里发生了什么？颜色是什么状态？前一个镜头在哪里结束，下一个镜头从哪里接？

## 2. 先做节拍表，再写代码
```
node tools/beatmap.mjs <from> <to>
```
它会打印这一段里的小节线、每一拍，以及每个字被唱出的时刻。
把这张表抄进你的设计说明，并在每一行旁边写上**这一刻发生什么**。
- 画面事件：切点、出现、落下、亮起、跳格……
- 字的事件：哪个字落在哪件实物上。
- 声音事件。
- 颜色状态的变化。

规则：
- 切点只落在拍或小节线上。
- 关键事件落在字的时刻上（`charTimes`）。
- 一段之内，"事件"的密度跟着音乐的能量走。

## 3. 镜头表
每个镜头写清楚这几项：
- `id` 和 `at`（必须在网格上）；
- `moment`：这是电话里的哪一刻；
- `layout`；
- 三层以上的内容：底、主体、前景或界面；
- 一个**有方向**的镜头运动，加上次级运动；
- 字落在什么实物上；
- 入场转场。

## 4. 先定关键帧，再加动作
1. 只做一帧静态的关键画面，按全尺寸渲染：
   `node export/export.mjs --sheet out/x.png --times T --cols 1 --width 1920 --height 1080`
   判断构图、层次、留白、颜色。不满意就改，**先别加动作**。
2. 构图定了，再加动作：镜头运动、雪、摇摆、错版回位、网点光的变化。

## 5. 逐拍缩图审片（必须真的看）
```
tools/sheet.sh <name> <每一拍的时间> 5
```
对照 `docs/VISUAL.md §6` 的验收清单：
- 每一格都在动；
- 字和人声对得上；
- 层次够；
- 没有超过两拍的静止画面；
- 颜色只在该变的时刻变。

至少迭代两轮。

## 6. 音效
在 `<section>Sfx(env)` 里声明。只给画面里的实物配声，`rel` 为负。然后跑 `node tools/sfx.mjs` 检查。

## 7. 交付总结
- 每个镜头做了什么；
- **哪里没有照要求做、为什么**；
- 需要的新素材或新音效种类。

不提交 git。

## 范例：`src/scenes/11_koi.js`（「恋色の空」，导演亲手按本流程做）
- **文件头就是节拍表**：每一行写一个时刻，以及那一刻发生什么。看代码之前，先看这张表。
- **事件锁在字上**：天空每唱一个字推进一档（`skyK`，只升不降）；每唱一个字，挂上一张纸签。
- **一个有方向的大运动**：镜头跟着她的视线往上摇（`tiltK`）。到了结尾的保持段，再加一个推近（`hold`），没有一刻是静止的。
- **分层视差**：天空、屋顶、电线、她、雪，各自用不同的速度移动。她离镜头最近，滑出得最快。
- **颜色状态有据可查**：`palette` 是一个随时间变化的函数，`state` 字段写明它在什么时刻怎么变。
- 和同一份任务书下 agent 做的版本相比，差别在于：
  - 颜色是一字一档**涨**上来的，不是一刀**切**过去的；
  - 「見上げたなら」是一个仰头的**动作**，不是一张静止的画。
